# Project contribution boundaries

Use synthetic data for local tests. Keep independent teams isolated. Preserve established scoring formulas, HR limits/Bands, rule versions, Beverage Board credits and audited corrections. Captain designation must not grant exclusive scoring privileges.

Prepare reviewable changes and verify them locally. The project owner must explicitly authorize commits, pushes, publication, deployment, paid actions, new services, live schema changes and authentication configuration changes for their specific scope. Coding permission alone does not authorize these actions. Do not send test emails or share records without approval.

Never commit credentials, private planning, test-account secrets, personal records or generated logs. Do not assume commercial hosting satisfies restricted government requirements. Preserve source material and avoid destructive changes.

Use the pinned lockfile and focused rule/browser/accessibility checks. A local build does not establish authenticated hosted acceptance, cross-device scoring synchronization or production readiness.
