# Private saved alibis: proposed persistence

The owner authorized the capability. Live schema application still requires review and approval of [the SQL proposal](personal_alibis.sql). It is intentionally outside the migrations directory and has not been applied.

One new table, `public.personal_alibis`, stores an account-owned UUID, optional title (80 characters), plain text (4,000 characters), one of the four existing categories, revision, last save command ID, and creation/update times. Ownership comes from the verified Supabase session and `auth.uid()`, never client input, nickname, team membership, captain status, or user metadata. Alibis have no game, team or season foreign keys. The account owner can reopen saved entries on another signed-in device.

RLS is enabled and forced. SELECT/INSERT/UPDATE/DELETE policies require the authenticated account to own the row; UPDATE has both USING and WITH CHECK. Column grants prevent ownership/ID reassignment. Two security-invoker RPCs with an empty search path implement revision-checked save/delete. Public and anonymous execution is revoked. Owner-indexed reads are paged, explicitly filtered by account. No service-role key, new service, auth configuration, Cloudflare binding or Access change is needed. Bio uses existing user metadata as plain profile text, never as authorization.

Saving generates a stable entry ID and command ID. An uncertain response retries the same payload and IDs. Concurrent edits return a conflict and preserve the draft for copying; refresh/reopen obtains the latest version. A repeated save does not add a second row. Delete requires an explicit second button and matching revision; repeated deletes succeed without disclosing whether another account owns the ID. Direct API writes are allowed only to the owner's rows; they retain ownership checks and constraints. RPC revisions protect the application editing flow, not a hostile account owner modifying their own entries directly.

Text is rendered by React as text, without HTML execution. No private browser-local persistence is added. Unsaved drafts disappear when leaving/reloading the page, which the UI states. Saved content is private from other app accounts and team members, but normal Supabase administration/backups can contain it. It is not end-to-end encrypted. Share invokes the device chooser only on an explicit click; Copy likewise requires a click. Sharing exports text, not a public alibi URL. Deletion removes the live row; existing platform backups follow the provider's retention. Deleting the Auth account cascades removal of its live alibis.

The editor stays usable for writing/generating/copying/sharing before schema setup. Saving is disabled until the table can be read, and it never reports persistence without a confirmed receipt. Community alibis and Alibi of the Week remain deferred.

Validation required before live application: disposable SQL tests for both owners and anonymous roles, forged ownership, owner reassignment, save retries, stale revisions, delete retries, constraints and account deletion; focused service/UI tests; Supabase security advisors against the eventual migration. The current shell cannot install pinned dependencies because its configured proxy is unreachable. No local SQL/build/browser pass is claimed until those checks actually run.
